# FridgeOut 面试讲解提纲

[返回产品展示](../README.md)

这份提纲帮助你围绕代码和设计讲项目。请只讲自己理解、验证过的部分；不要把示例测试结果说成线上效果，也不要把正在提交的 App 说成已经商业化成功。

## 90 秒介绍

> 我做了一个叫 FridgeOut 的移动产品，让用户拍摄冰箱里的食材，确认识别结果，再生成符合库存、饮食偏好和烹饪时间的菜谱。它还支持生成菜谱配图、收藏和离线删除同步，目前正在进行 iOS 发布和订阅测试。
>
> 技术上前端是 Expo、React Native 和 TypeScript，后端是 FastAPI。我用 LangGraph 把获取真实库存、生成、规则校验、模型评分和有限重试组织成有状态流程，通过 MCP 工具访问用户数据，Supabase 负责身份和数据隔离。
>
> 最值得讲的是把 AI 接入变成可靠产品：识别结果由用户确认才入库，菜谱同时经过确定性规则和模型评估；图片保存并复用，防止重复付费生成；离线删除用持久化 tombstone 防止数据重现；额度和订阅由服务器验证。我也使用了 AI 辅助开发工具，重点是我能解释设计取舍、失败路径和验证方式。

## 高频追问

### 这个为什么叫 Agent，而不只是调一个 LLM？

有状态、多步骤、工具提供真实上下文、校验反馈影响下一轮，并且有条件路由。但它是代码控制的有界工作流，不是模型自由决定调用所有工具，也不是多 Agent 互相辩论。可以坦诚说：用普通 Python 状态机也能实现；LangGraph 主要让状态、节点和循环边界更清楚。

### Guardrails、LLM 幻觉检查和 eval 是三套模型吗？

不是。Guardrails 是本地代码；LLM judge 是一次独立评分调用，当前与生成使用同一配置的文本模型；offline eval 是开发时运行的数据集和指标汇总。Judge 本身可以看漏，eval 的“幻觉率”目前主要是规则识别出的食材违规代理指标。

### 评分怎么算？能保证结果真实吗？

Prompt 要求五个维度取均值，指定违规时给零分，低于 0.75 不接受。当前服务器检查字段范围和 candidate index，但没有重新计算均值，因此不应声称数学上强制了评分公式。下一步可以服务器计算均值，再把违规标记作为单独拒绝条件。评分不是正确概率。

### 你怎么防止模型使用其他账号的食材？

模型不负责授权。API 校验 JWT，可信身份传到 MCP，工具参数不接受模型指定的任意 user ID，数据库再用 RLS 和归属约束隔离。后台 service-role 路径需要额外归属检查，因为它绕过 RLS。只在 Prompt 里写“不要读别人的数据”远远不够。

### 为什么照片识别不直接入库？

数量和单位是估计，错误会影响后续菜谱约束。把识别当提议，用户确认才写入，降低误识别成为持久状态的风险。代价是多一步操作，而且逐条保存仍有部分成功问题。

### 缓存如何降低生图费用？

云端保存是主事实来源，DB lease 协调生成任务，签名链接解决授权读取，本地文件缓存降低再次下载的等待。四者作用不同。缓存文件丢了应该下载；已经生成的云图片不应该再付费生成。Lease 也不能承诺所有远程超时下绝对 exactly-once。

### 离线删除为什么不会重新出现？

先持久化删除意图再隐藏条目，后续读取过滤 tombstone，网络恢复后重试服务器 DELETE。404 当作已经删除；临时失败继续等待；永久拒绝撤销 tombstone，再拉取权威数据。队列按账号隔离，切换账号时不能用新用户会话重放旧用户操作。App 关闭时不会继续同步。

### 怎么避免同时两个请求超额度？

不能只是读一个计数然后在代码里加一。用数据库事务做额度和预算预留，结合持久幂等键和任务结果复用。免费额度失败不扣，不代表模型调用没有成本；内部仍要记尝试费用和供应商实际 usage。

### 为什么不直接把完整代码开源？

这是计划收费的产品，所以公开产品体验、设计说明和少量教学示例，让面试官能判断理解和能力；完整实现独立维护。付费并不必然要求闭源，这是项目的公开范围选择。公开视频或面试演示可以补充运行效果，但不会提交服务密钥或用户数据。

## 可以现场演示的两段代码

```bash
python3 -m examples.recipe_constraints
python3 -m examples.offline_deletions
python3 -m unittest discover -s tests -v
```

1. [库存约束](../examples/recipe_constraints.py)：同一食材出现两次，分别不超库存，但合计超库存。解释为什么按单行检查不够。
2. [离线删除](../examples/offline_deletions.py)：模拟第一次网络失败，再次返回 404，观察条目保持隐藏、队列最终收敛；同时展示其他账号不受影响。

这些是专门为展示重写的简化示例，不要称为完整生产模块。

## 面试前自检

- 能画出一条请求从手机到模型、数据库的路线，指出每个身份边界。
- 能说明一个测试的失败场景，以及测试没有证明什么。
- 能讲出 MCP、轮询、规则词典、共享模型 judge 的替代方案和代价。
- 能区分“已经实现”“已在本地验证”“还需要设备验收”和“未来想做”。
- 如被问规模和收益，按实际情况回答；没有数据就不编造。
